# AstrBot 关键词回复

当前版本：`2.0.0`。作者：Rainfrost。

适用于 AstrBot 4.28.x、Python 3.12+、QQ / OneBot v11 的群聊文字回复插件。支持关键词直接回复和 `我吃什么 → 是啊吃什么` 这样的句式接话。

从1.x升级需要备份并按新表单重建规则，详见下方升级说明。新安装不需要迁移。

## 安装

在 AstrBot「插件 → 安装插件 → 本地上传」选择 `dist/astrbot_plugin_keyword_reply.zip`。也可把源码放到 `data/plugins/astrbot_plugin_keyword_reply`，安装 `requirements.txt` 后重新加载插件。

若群聊使用独立配置文件，请在该配置文件的「插件集合」中加入 `astrbot_plugin_keyword_reply`。全局插件开关打开后，仍可能被群配置过滤。

## 配置一条回复

全局仅有 **启用插件、群聊回复间隔、回复规则** 三项。回复间隔默认3秒，0表示不限；各群独立计时，发送成功后开始计时。

新增规则时选择以下一种；规则默认关闭，填完后启用。

| 项目 | 关键词回复 | 句式接话 |
| --- | --- | --- |
| 规则ID | `goodnight` | `echo` |
| 名称 | 晚安 | 句式接话 |
| 关键词 | `晚安` | 仅在限定词表时填写，例如 `吃`、`喝` |
| 句式 | 无需填写 | `我{关键词}什么` |
| 捕获内容 | 无需选择 | `any` 任意内容；`keywords` 仅限词表 |
| 回复 | `晚安，{用户名}！` | `是啊{关键词}什么` |
| 适用群 | 每项一个群号，空列表表示全部群 | 同左 |
| 需要@机器人 | 按需开启 | 同左 |

规则ID使用英文、数字、下划线或短横线，不要重复。回复可填多项，每次均匀随机选一项；只有一项时固定回复。常用配置只需填写ID、名称、触发内容和回复。

关键词模式只要消息包含任意一个词就命中；关键词是字面文字。句式必须完整匹配整条消息，且恰好包含一个 `{关键词}`，捕获1～128字符，不跨行、不接受纯空白。两种模式均去掉消息首尾空白，保留大小写和末尾标点。

句式选择 `keywords`，词表填 `吃`、`喝`：发送「我吃什么」回复「是啊吃什么」，发送「我学习什么」不回复。选择 `any` 时也能回复「是啊学习什么」。原需求中的 `[关键词]` 是示意，实际使用 `{关键词}`。

一条消息只回复一次：按规则列表顺序选第一条可用的命中规则，再随机选一条回复。需要@时，引用中的@、引用机器人、@全体都不算。只匹配顶层文字，引用正文不参与。

## 回复变量

| 变量 | 内容 |
| --- | --- |
| `{关键词}` | 命中的词或句式捕获内容 |
| `{匹配文本}` / `{消息}` | 匹配文字 / 原始消息正文 |
| `{用户名}` / `{用户ID}` | 发送者昵称 / QQ号 |
| `{群ID}` | 群号 |
| `{规则ID}` / `{规则名}` | 当前规则信息 |

`{{` 和 `}}` 输出字面花括号。变量仅替换一次，不执行表达式；未知变量会令该规则无效。每项回复可包含换行，仅发送纯文字。

## 聊天管理

仅 **AstrBot 配置中的机器人管理员** 可以执行，QQ群管理员身份本身无效。以下以 `/` 为前缀，实际以 AstrBot 唤醒配置为准。也可使用 `/关键词回复`。

| 命令 | 用途 |
| --- | --- |
| `/kwr list [页码]` | 查看本群规则，每页10条 |
| `/kwr off echo` / `/kwr on echo` | 关闭/恢复规则，作用于全部群 |
| `/kwr pause` / `/kwr resume` | 暂停/恢复插件，作用于全部群 |
| `/kwr test echo 我吃什么` | 测试一条规则 |
| `/kwr test all 我吃什么` | 测试全部规则 |
| `/kwr testat all 我吃什么` | 模拟直接@机器人测试 |
| `/kwr validate` / `/kwr reload` | 检查配置 / 重新读取配置 |
| `/kwr status` / `/kwr help` | 查看状态 / 帮助 |

测试只展示匹配和候选，不实际发送候选、不消耗冷却、不抽样、不修改开关。`on` 只能清除聊天指令造成的关闭，不能越过面板禁用或适用群限制。

普通消息即可触发。机器人自己的消息、以 `/` 开头的命令和管理命令不触发自动回复。成功发送后不追加 AstrBot 默认AI回复，其他插件仍可继续处理。

## 从1.x升级

2.0按基础用途删减了高级功能，**不兼容完整的1.x配置**。升级前备份 AstrBot 中的插件配置和 `data/plugin_data/astrbot_plugin_keyword_reply`。停用插件，将其旧配置文件移到备份目录，再加载2.0，让AstrBot生成默认配置，最后在面板按上面的两种表单重建规则。插件配置通常位于 `data/config/astrbot_plugin_keyword_reply_config.json`；使用多个配置文件时，以AstrBot实际加载的路径为准。

旧正则、整句关键词相等、前后缀匹配、优先级、概率、轮询、多规则连发、私聊、用户/平台筛选、排除词、分层开关等已删除。新版本不会把旧高级字段悄悄当成基础规则使用：全局旧字段会报告配置无效；包含旧字段的规则会被隔离。旧全局字段保留为隐藏升级标记，防止AstrBot提前清理而扩大触发范围；它们不提供任何可配置的高级功能。只在面板删除规则不能完成迁移，请先按上一段重置旧配置文件。

1.x运行状态保留为 `.corrupt-*` 备份，2.0暂时暂停自动回复，不继承原分层开关。重建并检查规则后由机器人管理员执行 `/kwr resume`。如果无需保留旧状态，可在升级前备份后移走该插件的状态目录。

2.0只保留一个群冷却，没有旧版每个用户10秒的规则冷却。群、平台实例和机器人之间仍隔离计时；同一事件ID去重120秒。失败不开始冷却，但已尝试发送的事件不会再次自动发送。面板修改会热应用；单条错误不影响其余规则，全局错误保留上次有效配置。

## 开发与发布

```powershell
python -m pip install -e ".[dev]"
python -m pytest tests --ignore=tests/integration -q
python -m ruff check .
python -m ruff format --check .
python -m scripts.version --check
python -m scripts.package
```

框架集成测试使用官方 AstrBot v4.28.1 源码放在 `.integration/AstrBot` 并安装其导入依赖。测试数据隔离，不连接真实QQ或模型。

每次发布推进版本：修复递增修订号，新增兼容功能递增次版本，不兼容修改递增主版本。例如：

```powershell
python -m scripts.version 2.0.1 --note "修复关键词匹配"
```

该命令同步插件版本、`metadata.yaml`、`pyproject.toml`、README当前版本及CHANGELOG。打包时强制检查一致性。`python -m scripts.build_schema` 重新生成表单，`python -m scripts.benchmark` 测量本机性能。

基础示例见 [examples/rules.json](examples/rules.json)。GitHub建仓设置、`.gitignore` 和许可证建议见 [docs/github.md](docs/github.md)。2.0验证记录见 [docs/acceptance-v2.md](docs/acceptance-v2.md)，历史1.0验收记录保留在 [docs/acceptance.md](docs/acceptance.md)。
