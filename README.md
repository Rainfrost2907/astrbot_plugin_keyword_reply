# AstrBot 关键词回复

QQ / OneBot v11 的文字自动回复插件，适用于 AstrBot 4.28.x、Python 3.12+。作者：Rainfrost。

支持关键词直接回复，以及 `我吃什么 → 是啊吃什么` 这样的句式接话。配置从 AstrBot 面板管理；普通群消息即可触发，单条规则可要求直接 @机器人。

## 安装

在 AstrBot「插件 → 安装插件 → 本地上传」选择交付 ZIP。也可把目录放到 `data/plugins/astrbot_plugin_keyword_reply`，确保 `main.py`、`metadata.yaml`、`_conf_schema.json` 位于该目录第一层。安装依赖 `requirements.txt` 后，在面板重新加载插件。

首次规则列表为空。新增规则默认禁用，填完后开启。支持的平台标识是 `aiocqhttp`，即 AstrBot 的 OneBot v11 适配器。

## 配置第一条句式

打开插件配置，在「回复规则」新增「句式」，填写：

| 字段 | 内容 |
| --- | --- |
| 唯一规则ID | `echo` |
| 规则名称 | 句式接话 |
| 启用 | 开 |
| 匹配方式 | `template` |
| 句式或正则 | `我{关键词}什么` |
| 捕获模式 | `keywords` |
| 关键词列表 | `吃`、`喝`，各一项 |
| 文字候选列表 | `是啊{关键词}什么` |

发送「我吃什么」回复「是啊吃什么」；发送「我学习什么」不回复。把捕获模式改为 `any`，即可回复「是啊学习什么」，默认捕获长度1～128字符，不跨行，不接受纯空白。

原需求里的 `[关键词]` 是示意，实际配置使用 **`{关键词}`**。句式必须恰好有一个该占位符。`full` 要求整段正文匹配，`search` 允许句式出现在正文中间。

## 直接回复与候选

新增「关键词」模板，填写关键词「晚安」，匹配方式 `contains`，回复候选分别填「晚安，{用户名}！」和「早点休息～」。每一项是一条候选，单项本身可包含换行。

| 匹配方式 | 含义 |
| --- | --- |
| `contains` | 正文包含任一关键词 |
| `exact` | 正文等于任一关键词 |
| `prefix` / `suffix` | 正文以关键词开头 / 结尾 |
| `template` | 固定句式中捕获词表或任意内容 |
| `regex` | 正则匹配，可使用编号及命名捕获组 |

默认去掉正文首尾空白；可忽略末尾连续 `?` / `？`，可忽略 ASCII 英文大小写。排除词只要出现一个就跳过。关键词是字面文本，不解释正则元字符。

回复候选支持 `first`（第一条）、`random`（均匀随机）、`round_robin`（按会话轮询）。轮询仅在发送成功后推进，并会持久化。

| 回复变量 | 内容 |
| --- | --- |
| `{关键词}` | 匹配的词或句式捕获内容 |
| `{匹配文本}` | 整段匹配文本 |
| `{消息}` | 原始顶层文字正文 |
| `{用户ID}` / `{用户名}` | 发送者QQ号 / 昵称，缺昵称回退QQ号 |
| `{群ID}` | 群号，私聊为空 |
| `{规则ID}` / `{规则名}` | 当前规则信息 |
| `{捕获.1}` / `{捕获.动作}` | 正则编号 / 命名捕获组 |

正则示例 `^我(?P<动作>.+?)什么$`，回复 `是啊{捕获.动作}什么`。`{{` / `}}` 输出字面花括号；变量不会再次解释，不执行表达式。未知变量使该规则无效。

## 限制作用范围

规则的群白名单填写群号字符串，空列表不限。群/用户黑名单优先于白名单；群限制不作用于私聊。平台列表填写 AstrBot **平台实例ID**，空列表不限。默认关闭私聊；启用时还需要规则聊天类型允许私聊。

「必须直接@机器人」只认可当前消息顶层的直接 @，引用机器人消息、引用内的 @、@全体成员均不满足。插件只拼接顶层文字，引用正文不参与匹配。

默认忽略以 `/` 开头的正文和机器人自己发送的消息。管理命令始终被识别，不能触发自动规则。

## 优先级、概率与冷却

默认多规则选择 `priority`：优先级越大越先，同级按面板列表顺序，只回复一条。`random` 从符合条件的规则中均匀选一条；`all` 按顺序回复，默认最多3条。每条规则概率取0～1：0永不参与，1必定参与；每次消息只抽样一次。

冷却检查先于选择，高优先级规则在冷却或概率未通过时，低优先级可接替。默认会话总冷却3秒、会话内用户本规则冷却10秒、会话内本规则冷却0秒；0表示关闭相应冷却。只有实际成功发送才开始冷却。

会话由平台实例、机器人QQ、聊天类型和群号/私聊用户共同隔离。按消息ID去重120秒，不按相同正文去重。至少尝试发送的消息保留去重，即使网络失败也不自动重试；冷却和失败游标不推进。插件重载时冷却、去重和统计清零，管理开关与轮询游标保留。

## 管理与诊断

全部命令仅允许 **AstrBot 配置中的机器人管理员**；仅QQ群管理员没有此权限。命令前缀以 AstrBot 的唤醒配置为准，以下以 `/` 为例。中文别名 `/关键词回复` 与 `/kwr` 相同。

| 命令 | 操作 |
| --- | --- |
| `/kwr help` | 用法 |
| `/kwr list [页码]` | 当前会话适用规则，每页10条 |
| `/kwr show echo` | 规则详情及当前限制 |
| `/kwr on echo [here\|global]` | 清除该层运行禁用 |
| `/kwr off echo [here\|global]` | 运行禁用 |
| `/kwr pause [here\|global]` | 暂停自动回复 |
| `/kwr resume [here\|global]` | 清除该层暂停 |
| `/kwr reset [here\|global]` | 清除该层暂停与禁用覆盖 |
| `/kwr test echo 我吃什么` | 测试指定规则 |
| `/kwr test all 我吃什么` | 测试全部规则 |
| `/kwr testat all 我吃什么` | 模拟直接 @机器人测试 |
| `/kwr validate` | 查看当前配置错误 |
| `/kwr reload` | 从配置文件重新读取 |
| `/kwr status` / `/kwr stats [ID]` | 状态 / 全部或指定规则本次加载以来统计 |

默认 `here` 仅当前会话；`global` 必须明确指定。`on`/`resume` 不解除面板禁用、黑名单或另一层暂停。`reset` 不清冷却、去重及轮询。

`test` 展示捕获、候选和阻挡原因，候选属于诊断文字，不会逐条实际发送。它不抽样、不消耗冷却、不推进轮询、不增加正式统计、不写状态文件。报告最多4000字符，可指定规则ID缩小范围。

## 保存、升级与共存

面板保存后，插件每2秒检查配置文件变化并应用；AstrBot 完整重载也会重新加载。单条非法规则被隔离，其余规则继续运行；非法全局配置保留上次有效配置。首次全局配置无效时自动回复关闭，管理指令仍可用。修复暂时无效的规则不会清掉其运行禁用。

状态存储在 `data/plugin_data/astrbot_plugin_keyword_reply/<配置路径哈希>/state.json`。管理开关立即原子保存；轮询每30秒及卸载时保存。升级前备份插件配置和这个数据目录。更换配置文件路径会得到独立状态；修改规则ID视为新规则。损坏状态会备份为 `.corrupt-*` 并暂停自动回复，检查后使用 resume 恢复。

成功回复使用框架公开发送接口，AstrBot 4.28 默认AI不会再追加一条回复；其他插件仍可处理消息。未命中、冷却、正则超时或发送失败时，原有AI流程继续。其他插件主动调用LLM或自行发送仍遵循其自身行为。

首版仅文字，不发送图片、表情组件、语音、文件或真正的 @；候选中的CQ码也按文字发送。最多500条规则，输入默认4096字符，回复默认2000字符。正则与总评估有超时预算，匹配工作并发最多2个，忙时跳过自动回复。

完整示例在 [examples/rules.json](examples/rules.json)，四条均默认关闭。验收证据见 [docs/acceptance.md](docs/acceptance.md)。

## 开发验证

安装 `pip install -e ".[dev]"` 后运行 `python -m pytest tests --ignore=tests/integration -q`。框架集成测试需要官方 AstrBot v4.28.0 源码放在 `.integration/AstrBot` 并安装其导入依赖；测试隔离运行数据到 `.integration/runtime`，不连接真实QQ或模型。

运行 `python -m ruff check .`、`python -m ruff format --check .`。从项目根目录运行 `python -m scripts.build_schema` 可重新生成表单；`python -m scripts.benchmark` 输出本机评估性能。
