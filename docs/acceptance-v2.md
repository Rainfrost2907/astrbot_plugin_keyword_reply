# 2.0.0精简版验证记录

验证日期：2026-09-30。用户选择“删除多数高级功能，只留基础回复”。这是2.0的本地代码与框架集成验证，未重新安装到实际QQ环境；1.0的真实群回复结果不等同于2.0验收。

## 配置与行为

- 全局3项：启用、群聊回复间隔、回复规则。
- 关键词规则7个可见字段；句式任意捕获8个，限定词表9个。
- 保留关键词包含、整句句式、任意/词表捕获、随机文字候选、变量、适用群和直接@。
- 按列表顺序只回复第一条可用命中规则。保留一个群冷却、固定去重和工作并发保护。
- 删除正则及捕获组、优先级、多规则选择/连发、概率、轮询、私聊、用户/平台筛选、排除词、分层运行开关和高级统计命令。
- 旧高级字段明确报告而不是忽略。旧运行状态原样备份并暂停，新版开关只作用于全部群。

## 可复现证据

在Windows、Python 3.12.10和官方AstrBot v4.28.1本地依赖环境执行：

```powershell
.\.venv\Scripts\python.exe -m pytest tests -q -p no:cacheprovider --basetemp .test_runs/v2_final
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m ruff format --check .
.\.venv\Scripts\python.exe -m compileall -q main.py keyword_reply scripts
.\.venv\Scripts\python.exe -m scripts.version --check
.\.venv\Scripts\python.exe -m scripts.benchmark
```

结果：144项测试通过（120单元+24框架集成），2条上游弃用警告；Ruff通过，43个Python文件已格式化，编译通过，版本文件均为2.0.0。测试覆盖新表单、捕获、范围、顺序与随机、并发、冷却/去重、发送失败、管理员权限、无副作用诊断、旧状态备份、原子写入失败，以及版本同步和回退拒绝。

精简约束先在1.0实现上观察到13项失败，删除对应功能后13项通过；版本同步工具先观察到2项失败，再实现并通过。测试移除了对应已删除功能的旧断言，保留发送、热更新、并发、存储与框架共存验证。

独立只读复核发现框架原生加载会清理旧全局字段，以及后台保存会把null标记改写为空字符串。均先增加真实框架回归测试并观察失败，再改为隐藏的专用字符串升级标记。12项旧字段在原生加载后均被拦截，新版表单经真实后台验证保存后仍然有效；升级标记不显示在面板，也不提供高级功能。复核最终确认无遗留问题。

性能：30次预热后执行1000次，500关键词规则/4096字符未命中消息p95为0.775ms；400关键词+100句式p95为0.771ms。100次并发请求98次立即繁忙、2次正常评估，工作许可恢复为2。该结果不包含QQ网络发送耗时。
