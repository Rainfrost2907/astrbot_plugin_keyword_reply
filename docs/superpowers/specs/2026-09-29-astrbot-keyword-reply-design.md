# AstrBot 关键词回复插件设计说明

日期：2026-09-29。状态：需求已确认，供实施计划和后续开发使用；本次只编写文档。

## 1. 已确认需求

| 项目 | 决定 |
| --- | --- |
| 运行环境 | QQ、OneBot v11、AstrBot 4.28，主要用于群聊 |
| 句式回复 | 同时支持限定关键词列表，以及捕获任意内容后填入回复 |
| 直接回复 | 命中指定关键词后，发送配置好的文字 |
| 配置入口 | AstrBot 原生管理面板；聊天指令负责查看、开关、测试 |
| 回复内容 | 首版仅文字，支持多条候选、随机选择、变量替换 |
| 触发条件 | 普通群消息可以触发；每条规则可以要求必须直接 @机器人 |
| 管理权限 | 仅 AstrBot 配置中的机器人管理员；QQ群主、群管理员身份不自动获得权限 |
| 冲突策略 | 默认按优先级只回复一条；可切换随机一条、命中多条 |
| AI 与插件 | 成功回复后不追加 AstrBot 默认 AI 回复，其他插件仍可处理 |
| 默认限制 | 群冷却 3 秒；同用户同规则冷却 10 秒；可以设为 0 |
| 默认句式语义 | 整句匹配、捕获不能为空；相同优先级按配置顺序 |
| 多条回复 | 默认最多 3 条；这是本插件的上限，不包含其他插件发送的消息 |

## 2. 方案选择与首版范围

采用「原生配置表单＋独立规则引擎＋薄事件适配层」。简单关键词字典不能满足句式捕获；自建管理网页会增加前端、接口和兼容成本，因此首版采用原生表单。

插件暂定名 `astrbot_plugin_keyword_reply`，展示名「关键词回复」，版本从 `1.0.0` 开始。命令主名 `kwr`，中文别名「关键词回复」。

首版必须包含：

- 精确、包含、前缀、后缀、句式模板、正则六种匹配模式。
- 规则独立开关、固定 ID、名称、优先级、命中范围、排除词。
- 群聊和私聊范围、平台实例限制、群和用户黑白名单。
- 必须直接 @机器人开关、忽略自身消息、忽略指定账号。
- 固定回复、候选随机回复、轮询回复、变量替换。
- 优先级单条、随机单条、多条限量三种冲突策略。
- 触发概率、群冷却、规则在群内的冷却、用户在群内对单条规则的冷却。
- 事件去重、并发保护、正则超时、输入与输出长度上限。
- 管理员查看、开关、恢复、校验、测试、状态和统计指令。
- 原生配置保存后应用、规则编译缓存、无效配置隔离、运行状态持久化。
- 中文配置提示、示例规则、安装说明、行为测试和真实 OneBot 验收清单。

首版不包含图片、语音、文件回复，不自动调用 AI 生成回复。不包含群成员自助教学、聊天增删改规则、自定义网页、远程规则订阅、复杂条件表达式、定时任务、跨消息对话状态。模板多变量捕获通过高级正则实现；普通句式模板首版只提供一个 `{关键词}` 槽位。

## 3. 使用示例与语法

### 3.1 限定关键词的句式

面板填写：模式「句式模板」；检测句式 `我{关键词}什么`；捕获模式「词表」；词表 `吃`、`喝`；回复 `是啊{关键词}什么`。

| 输入 | 结果 |
| --- | --- |
| 我吃什么 | 是啊吃什么 |
| 我喝什么 | 是啊喝什么 |
| 我学习什么 | 不命中 |
| 我什么 | 不命中 |
| 今天我吃什么 | 默认不命中；将匹配范围改为「消息中搜索」后命中 |

`[关键词]` 是需求里的示意写法，实际表单统一使用 `{关键词}`。面板提示和示例必须明确这一点。

### 3.2 捕获任意内容

检测句式仍为 `我{关键词}什么`，捕获模式改为「任意内容」。

- `我学习什么` → `是啊学习什么`。
- `我今天中午吃什么` → `是啊今天中午吃什么`。
- 捕获默认 1～128 个 Unicode 字符，不跨换行；长度可以配置在 1～1024 内。
- 固定文字按字面匹配，括号、句点等不会自动变成正则。
- 模板必须且只能包含一个 `{关键词}`；固定文字需要字面大括号时写 `{{` 和 `}}`。
- 默认仅裁掉消息整体首尾空白，不删除句内空白，不转换简繁，不剥离问号。
- `我吃什么？` 在默认整句模式下不命中。可选「忽略末尾问号」，仅删除末尾连续 `?`、`？`；搜索模式不需要该选项。
- 空白组成的捕获视为无效；真实捕获保留原有文字与大小写。

### 3.3 关键词直接回复

例如「包含」模式、词表 `晚安`、候选回复 `晚安，{用户名}！` 和 `早点休息～`。输入 `大家晚安` 会从候选中选一条。

精确模式要求全文等于词表中的一个词。前缀、后缀模式分别要求以一个词开头或结尾。多个词默认 OR；若同一规则命中多个词，取最靠左的命中，位置相同取最长，再相同按词表顺序，保证 `{关键词}` 稳定。

排除词为字面包含判断，任一排除词出现即跳过该规则。首版不提供含糊的模糊匹配，也不自动中文分词。

### 3.4 正则与变量

正则示例：`^我(?P<动作>.+?)什么$`，回复 `是啊{捕获.动作}什么`。支持「全文匹配」与「消息中搜索」，捕获使用 `{捕获.1}`、`{捕获.2}` 或 `{捕获.名称}`；第 0 组通过 `{匹配文本}` 使用。未参与匹配的可选组替换为空字符串。

| 变量 | 含义 |
| --- | --- |
| `{关键词}` | 普通模式选中的词；模板捕获内容；正则模式取整段匹配文本 |
| `{匹配文本}` | 实际命中的整段正文 |
| `{消息}` | 本次消息的原始提取正文，不包含引用内容和非文字消息段 |
| `{用户ID}` | 发送者 QQ 号，字符串 |
| `{用户名}` | 平台提供的发送者名称；缺失时用用户 ID |
| `{群ID}` | QQ 群号；私聊为空字符串 |
| `{规则ID}` / `{规则名}` | 当前规则信息 |
| `{捕获.1}` / `{捕获.名称}` | 仅正则捕获组 |

模板只允许上述变量，禁止表达式求值、属性访问、函数调用。未知变量、括号不平衡、引用不存在的捕获组在编译规则时报告字段错误。替换只执行一遍：捕获到的 `{用户ID}` 本身仍是普通文字。发送使用 Plain 文字组件，不把捕获内容解释成 CQ 码或指令。

## 4. 配置结构与默认值

原生 `_conf_schema.json` 使用扁平的根级字段，通过描述前缀「基本设置」「运行限制」和字段顺序组织；`rules` 使用 `template_list`，提供「关键词」「句式」「正则」三个添加入口。每条规则也保存为扁平字段，不额外嵌套一套 UI 数据结构。保存数据中的 `__template_key` 只用于识别表单模板，不参与业务判断。

### 4.1 全局配置

| 字段 | 默认值 | 约束 / 语义 |
| --- | --- | --- |
| `enabled` | true | 面板总开关；运行时指令不能越过它 |
| `allow_private` | false | 默认仅群聊；管理员私聊管理命令不受自动回复开关限制 |
| `selection_mode` | priority | priority / random / all |
| `max_replies` | 3 | 1～10；仅 all 生效 |
| `group_cooldown_seconds` | 3.0 | 0～3600；私聊开启后按对端会话隔离 |
| `dedup_ttl_seconds` | 120 | 10～600 |
| `max_input_chars` | 4096 | 128～16384；超限跳过，不截断后误匹配 |
| `max_reply_chars` | 2000 | 1～4000；超限跳过该候选，不静默截断 |
| `regex_timeout_ms` | 10 | 1～50；每次匹配超时 |
| `evaluation_budget_ms` | 100 | 20～500；整次匹配的总预算，耗尽则本事件不自动回复 |
| `max_rules` | 500 | 固定首版上限，超过后本次配置不应用 |
| `ignore_command_prefixes` | ["/"] | 原始正文以这些前缀开头时不自动回复；管理命令始终单独识别 |
| `blocked_user_ids` | [] | 全局忽略账号，可填写其他机器人 QQ 号 |
| `platform_ids` | [] | 空表示所有 OneBot 实例；非空只在选中实例工作 |

去重键为 `(平台实例ID, 机器人账号ID, 消息类型, 群/私聊对端ID, 消息ID)`。消息 ID 缺失时跳过去重并计数，不按正文散列去重，避免屏蔽用户真实重复发送。

### 4.2 规则字段

| 分类 | 字段和默认值 |
| --- | --- |
| 标识 | `id` 必填、唯一，1～64 个 ASCII 字母/数字/下划线/短横线；`name` 必填；`enabled=true`；`priority=0`，范围 -10000～10000 |
| 模式 | `match_type=contains`；`keywords=[]`；`pattern=""`；`match_scope=full`（模板/正则使用） |
| 模板 | `capture_mode=any`（any / keywords）；`capture_min=1`；`capture_max=128` |
| 文本选项 | `ignore_case=false`（ASCII 大小写）；`trim=true`；`ignore_trailing_question_marks=false`；`exclude_keywords=[]` |
| 来源 | `chat_types=group`（group / private / both）；`require_at=false`；`platform_ids=[]` |
| 范围 | `allowed_group_ids=[]`；`blocked_group_ids=[]`；`allowed_user_ids=[]`；`blocked_user_ids=[]` |
| 回复 | `replies` 为非空文字列表；`reply_mode=random`（first / random / round_robin） |
| 门槛 | `probability=1.0`，0～1；`group_rule_cooldown_seconds=0`；`user_rule_cooldown_seconds=10`，均为 0～3600 |

空白名单表示不限制，黑名单优先。群名单只对群聊生效；私聊需要全局允许且该规则允许私聊。`require_at` 对群聊检查真实 At 组件且对象等于机器人，AtAll、引用机器人消息、正文中的文字“@机器人”均不算；私聊无需 At。

`ignore_case` 在普通词和模板模式中只折叠 ASCII A-Z，返回捕获仍保留原文字形。高级正则开启该项时使用 `regex.IGNORECASE | regex.ASCII`，因此 `\w`、`\d` 等字符类也采用 ASCII 语义；匹配中文时使用明确文字或相应字符范围。此差异必须在正则配置提示中说明。

规则总数≤500；每条词表≤200 个非空词，每词≤256 字符；模式文本≤1024 字符；每条回复≤2000 字符、候选≤50；排除词同词表限制。群号和用户号使用字符串，禁止浮点数转换造成 ID 精度变化。

启用规则必须具有有效配置。示例规则以禁用状态提供，但也必须语法有效。重复 ID 或全局配置错误拒绝整个新快照；某一条规则字段错误时隔离该规则，其余有效规则可以应用，并在校验和状态中明确列出错误。首次加载全局失败时保持自动回复停用，保留管理员诊断命令。

## 5. 处理流程与冲突语义

1. 管理命令先识别、鉴权；管理命令正文绝不进入自动回复引擎。
2. 确认是 OneBot 消息；忽略自身发送、全局屏蔽用户、超长正文和无正文事件。
3. 从顶层 Plain 组件依序拼接正文；不抓取 Reply、Forward 内嵌文字，不识别图片文字。保留原始正文副本。At 只用于判定触发条件。
4. 取一次不可变配置快照和一次运行状态视图。所有群状态以 `(平台实例, 机器人账号, group_id)` 隔离，不用可能启用“独立会话”的 `session_id` 代替群号。
5. 检查全局启用、运行时暂停、群/用户范围、At 条件、命令前缀、去重和群冷却。
6. 按优先级降序、配置顺序升序遍历；进行排除词、匹配、渲染非空候选、单规则冷却检查与概率抽样。
7. 概率每规则每事件至多抽样一次；0 永不回复、1 总是通过。冷却或概率不通过的高优先级规则不会挡住其他合格规则。
8. priority 取第一条合格规则；random 从所有合格规则均匀随机取一条，明确忽略规则优先级；all 按排序取最多 `max_replies` 条。
9. 每条选中的规则按 first / random / round_robin 选一个有效候选。随机允许连续选中同一候选；轮询按群＋规则保存游标。
10. 原子预留去重、群冷却与选中规则的发送资格，阻止并发消息同时穿透。按选定顺序发送，不创建延迟消息队列。
11. 发送成功后提交对应规则冷却、轮询游标和统计。至少一条成功才提交群冷却。发送失败记录发送错误，不提交失败规则的冷却或游标；不自动重试、不临时改发另一条规则。
12. 已尝试发送的事件无论成功失败均在去重 TTL 内保留，避免回执不明引起重复发送；未尝试发送的事件释放短期预留。异常释放锁和发送资格。

在 all 模式，群冷却针对一次入站事件，不阻止该事件已经选中的第 2、3 条规则；另一条入站消息必须等待资格检查。新消息遇到该群正在发送时直接跳过并记录 busy，不排队补发。

不因自动匹配成功调用 `stop_event()`。发送成功不主动调用 LLM；未命中、概率失败、冷却、配置无效、超时或发送失败不主动改变 LLM 开关。其他插件仍有权自行回复或调用 LLM，本插件不能保证整个机器人只发送一条消息。

## 6. 管理、配置应用与数据

### 6.1 管理命令

下面 `/` 是常见 AstrBot 唤醒前缀，实际跟随用户的框架配置。指令均要求 `event.is_admin()`，不能只依赖 QQ 群角色。

| 命令 | 行为 |
| --- | --- |
| `/kwr help` | 说明用法、权限和命令作用范围 |
| `/kwr list [页码]` | 分页列出本会话适用规则的 ID、名称、优先级、有效状态，每页 10 条 |
| `/kwr show <ID>` | 显示配置、匹配示例、冷却和运行时禁用来源 |
| `/kwr on <ID> [here\|global]` | 默认 here；清除当前会话或全局的运行时禁用 |
| `/kwr off <ID> [here\|global]` | 默认 here；在当前会话或全部会话运行时禁用该规则 |
| `/kwr pause [here\|global]` | 默认 here；暂停本会话或全部自动回复 |
| `/kwr resume [here\|global]` | 默认 here；解除相应运行时暂停 |
| `/kwr reset [here\|global]` | 清除相应层级的暂停与规则禁用，恢复面板基础配置 |
| `/kwr test <ID\|all> <消息原文>` | 只返回诊断报告，不实际发送候选回复 |
| `/kwr testat <ID\|all> <消息原文>` | 与 test 相同，模拟本条测试正文直接 @机器人 |
| `/kwr validate` | 列出配置校验结果；不修改配置 |
| `/kwr reload` | 读取面板配置文件并编译、原子应用；失败保留旧的可用快照 |
| `/kwr status` | 配置摘要、当前群隔离键、暂停状态、有效/无效规则数 |
| `/kwr stats [ID]` | 本次启动以来的匹配、成功、冷却/概率跳过、超时和发送失败统计 |

here 在群聊指当前群，在管理员私聊指该私聊会话；global 必须显式填写。面板 `enabled=false`、规则面板禁用、黑名单和范围限制始终是上限；on/resume 不会强行开启面板禁用项，报告中解释仍未启用的原因。

test 使用当前管理员的身份和当前会话范围，报告匹配文本、变量、候选回复、排序、是否冷却、概率值及配置错误。probability 不抽样，输出「正常运行通过概率为 X」；随机候选展示可选列表，轮询只读取下一位置。不更新去重、冷却、统计、游标、运行状态或正式随机数生成器。

测试解析必须保留测试正文中的空格、引号与换行，不把整个正文交给 shell 风格分词。报告中的候选以纯文本展示，分页或截断展示并标注原长度，不能把管理测试变成一串自动回复。

### 6.2 配置与运行数据分离

面板配置是规则的唯一来源。聊天开关只保存负向限制，不修改面板的规则 JSON，避免面板和聊天修改丢失。

运行数据写入 `data/plugin_data/astrbot_plugin_keyword_reply/<profile_hash>/state.json`；不得写入插件代码目录。profile_hash 为规范化绝对配置路径的 SHA-256 前 16 位。使用版本为 1 的状态格式，包含全局暂停、全局禁用规则集合、会话暂停/禁用集合、轮询游标。写入通过同目录临时文件＋原子替换；保存失败回滚该次管理变更并报告失败。损坏状态保留备份，以自动回复暂停的状态恢复，允许管理员诊断和恢复。

冷却、短期去重、概率 RNG 和统计保存在内存；机器人完整重启后清零。配置热应用不清空仍存在规则的冷却或去重，删除规则时清理孤立状态。轮询游标定期合并写入，最多 30 秒一次，正常卸载时刷盘；异常退出允许丢失最近 30 秒的轮询进度，不保证断电严格轮询。

每 2 秒检查注入 `AstrBotConfig.config_path` 指向文件的修改时间；发生变化时在工作线程读取、校验、编译，再一次性换掉快照。文件半写入或 JSON 解析失败保留旧快照，下一轮重试。插件只读框架配置文件，不自行重写。框架重载插件时取消本插件后台任务，再由新实例加载，确保不出现重复监听和重复轮询。

状态按配置文件路径摘要分区，避免 AstrBot 多份配置方案串用运行开关。同一进程、同一分区的写操作必须串行；首版不支持多个 AstrBot 进程共用同一可写数据目录。

每次写入带递增状态 revision，旧的游标刷盘快照不能覆盖较新的管理开关。更换配置后，已经获得发送资格的事件可以完成这一轮发送；删除规则后不允许在途事件重新写回已删除规则的持久状态。候选列表发生变化时，以新列表长度对已有轮询游标取模。

### 6.3 资源限制与故障隔离

正则使用带原生 timeout 的 `regex` 库，不用 `asyncio.wait_for(re.search(...))` 冒充可取消的正则计算。模板和正则都在有限工作线程中匹配；最多同时评估 2 个事件，忙时跳过自动回复，不无限创建后台任务。每次正则最多 10ms、每事件匹配预算默认 100ms；预算耗尽舍弃本次候选，避免半套规则决定回复。

本插件错误日志包含规则 ID、错误码和字段路径，默认不记录完整群消息。重复错误限频。内存缓存最多保存 10000 条去重项、10000 个冷却/会话条目，按过期时间和最近使用清理；发生淘汰计数可在 status 中看到。持久化管理开关不静默淘汰；最多 10000 个会话分区，超出时拒绝新的管理写入并提示。

## 7. AstrBot 4.28 接入边界

- Python 3.12 开发基线；插件声明 AstrBot `>=4.28,<4.29`，只承诺验证过的 4.28 系列。
- 插件继承 Star，入口 main.py，元数据 metadata.yaml，原生配置 _conf_schema.json。内部引擎不依赖 AstrBot，便于单元测试。
- 消息入口监听 ALL 并限制 AIOCQHTTP；私聊是否自动回复由配置控制。管理命令优先级高于自动监听，并在处理后标记本插件管理事件，防止其正文二次匹配。
- 发送使用 `await event.send(event.plain_result(text))`，仅构造 Plain，不通过文字转图片、自动 At、全局结果装饰流程；这是首版纯文字输出的明确行为。
- 4.28.0 的默认 Agent 入口检查 `_has_send_oper`；OneBot 的 send 成功会调用基类 send 设置该标志，因此正常公开发送接口已能抑制同事件的默认 AI。插件不直接写这个私有字段。
- `should_call_llm` 的名称与 4.28 消费端逻辑容易混淆，不凭方法名称猜测布尔值；首版不依赖该方法实现抑制。
- 不阻止其他插件主动发起 LLM 请求，不取消已经启动的其他插件请求，不绕过 AstrBot 本身的白名单、插件集、平台事件过滤或全局限流。
- OneBot 是协议而非具体实现。用户未指定底层实现；真实验收在用户实际使用的 OneBot 实现上执行，不擅自标记 NapCat 等实现已验证。

## 8. 验收标准

| 类别 | 必须通过的行为 |
| --- | --- |
| 原始需求 | 词表模式我吃什么→是啊吃什么；任意模式我学习什么→是啊学习什么；关键词晚安直接回复 |
| 边界 | 空捕获、空白捕获、超长捕获不命中；字面正则符号不被解释；中文与 Emoji 正常 |
| 匹配 | 六种模式、全文与搜索、ASCII 大小写、问号开关、排除词均按定义 |
| 模板 | 捕获值不二次求值；未知变量加载时报错；不可用正则组报错；可选组为空 |
| 来源 | 原始唤醒前缀不丢失；引用内容不触发；AtAll/引用不能替代直接 At；忽略自身 |
| 范围 | 黑名单高于白名单；私聊默认关闭；同群不同 OneBot 实例/账号不串冷却；独立会话开关不拆散群冷却 |
| 冲突 | 优先级降序、同级配置顺序；高优先级冷却后低级可接替；随机模式、all 上限正确 |
| 运行 | 并发只让一个群事件获得发送资格；失败不推进游标；重复投递不重复回复 |
| 诊断 | test 不修改任何正式运行状态；testat 正确模拟 At；权限不足不泄露规则正文 |
| 管理 | here/global 正确隔离；运行开关不覆盖面板；禁用项不能由 on 越过；重启保留管理状态 |
| 配置 | 局部错误隔离、全局错误保留旧快照；热应用不中断在途事件；重载无重复任务 |
| 框架 | 未命中允许原框架处理；成功回复不追加默认 AI；其他插件继续；发送异常不停止整条消息 |
| 性能 | 500 条普通规则×4096 字符消息基准，记录机器与耗时；普通规则评估目标 p95<50ms（不含 QQ 网络） |
| 超时 | 病态正则被超时控制；后台队列不增长；配置/命令在匹配超时时仍能响应 |

性能指标是后续测试目标，本次规划没有测量或宣称达成。
